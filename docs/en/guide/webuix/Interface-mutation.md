# Interface Prototyping and Mutation

WebUI X **v647** supports **mutable objects and class prototyping** for the native `ksu` JavaScript interface. This allows you to extend underlying system classes, inject custom polyfills, and instantiate native utility classes directly within your frontend scripts.

## The `ksu.cls` Registry

All core classes available for prototype extension are mapped inside the **`ksu.cls`** object registry. Modifying a prototype within this registry globally affects all subsequent instances generated by the `ksu` bridges (such as `ksu.io()`).

## Extending Core Interfaces

You can inject new methods directly into a specific class prototype. This is useful for adding shortcut operations or high-level wrappers around native logic.

### Example: Single Interface Extension

```js
// 1. Define a new custom method on the prototype
ksu.cls.FileInputStream.prototype.forceClose = function (id) {
  // Custom wrapper logic here
};

// 2. Instantiate and use the new method
const streamInterface = ksu.io().FileInputStream();
const streamId = streamInterface.open("/sdcard/test.txt");

streamInterface.forceClose(streamId);
```

### Example: Batch Extension (Kotlin-style `.use()` block)

You can loop over multiple interface prototypes to implement shared utility functions, like a self-closing resource manager:

```js
const StreamInterfaces = ["FileInputStream", "FileOutputStream"];

// Batch apply a custom `.use()` resource management method
for (const face of StreamInterfaces) {
  ksu.cls[face].prototype.use = function (callback) {
    try {
      return callback.call(this);
    } catch (e) {
      throw e;
    } finally {
      this.close(); // Automatically clean up resource
    }
  };
}

// Usage with FileInputStream
ksu
  .io()
  .FileInputStream()
  .use(function () {
    this.read();
    return "1";
  });

// Usage with FileOutputStream
ksu
  .io()
  .FileOutputStream()
  .use(function () {
    this.read();
    return "1";
  });
```

## Mutating Bridge Interfaces

Prototype mutations also apply to backend bridges like `ksu.io()`. You can alter core prototype behaviors globally to mock data, force fallback behaviors, or gate features.

```js
// Force IO operations to declare a version of 0 (unsupported)
ksu.cls.IO.prototype.version = function () {
  return 0;
};

// Any future ksu.io() instance inherits this behavior
const ver = ksu.io().version();
console.log(ver); // Outputs: 0 (unsupported)
```

## Instantiating Utilities via `ksu.cls`

Aside from prototype modifications, `ksu.cls` acts as a direct entry point to instantiate utility abstractions.

### Using `ksu.cls.File(path: string)`

```js
// Instantiates a reference to a filesystem entity
const file = ksu.cls.File("/sdcard/test.txt");

console.log(file.exists()); // Returns boolean
console.log(file.isFile()); // Returns boolean
```
